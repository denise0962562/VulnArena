# 靶场关卡设计（借鉴成熟靶场的做法）

> 目标：把现在"一场演练打 8 步"升级成"分层闯关"——每层蓝队出题、红队破解，
> 解完才开下一层。这份文档记录借鉴了谁、抄什么、不抄什么，以及我们自己的分层。

## 1. 调研：成熟靶场怎么设计

| 平台 | 核心结构 | 值得抄 | 不抄 |
|---|---|---|---|
| **PortSwigger Web Security Academy** | 按漏洞主题分模块，每个 lab 分 apprentice / practitioner / expert 三档难度，先给场景再给目标 | **难度分档 + 单一知识点聚焦**：「一个 lab 只教一件事」 | 每个 lab 独立部署（成本高） |
| **TryHackMe** | room = 一组引导式任务，带学习路径（path）串起来 | **任务清单 + 进度标记**，以及"先看任务描述再动手"的节奏 | 依赖虚拟机的重靶场 |
| **Hack The Box** | machine 有难度等级，解题给 XP，XP 累积成 rank | **难度 × 分数 + 段位**，让人有长期目标 | 真实主机、需要 VPN 的环境 |
| **CTFd / 常规 CTF** | challenge + 分值 + hint（提示要扣分） | **提示有成本**，抄答案的人拿不到满分 | 纯 flag 提交（我们更看重过程） |
| **Vulhub / Vulfocus** | 一条命令拉起某个 CVE 的复现环境 | **CVE 即题目**，将来可作为外部靶标配 manifest 挂进来 | 与本项目业务靶场混在同一进程 |

结论：我们抄 **PortSwigger 的难度分档** + **TryHackMe 的任务清单** + **CTFd 的提示扣分**，
不抄它们的部署形态（一律进程内、可复原）。

## 2. 我们的分层（Tier 1 → 5）

每一层对应"蓝队出的题"，判定**查数据库状态或 canary**，不看 flag 字符串。

| 层 | 关卡 id | 主题 | 蓝队开启的缺陷 | 判据 | 分值 |
|---|---|---|---|---|---|
| L1 | `auth-bypass` | 身份边界 | `sqli_login_bypass` | 拿到 cfo 角色会话 | 10 |
| L2 | `data-injection` | 注入与数据泄露 | `sqli_search` | 响应里出现 canary | 20 |
| L3 | `broken-access` | 越权 | `idor_po_detail` | 读到别人的单据（含备注） | 30 |
| L4 | `logic-flaw` | 业务逻辑 | `mass_assignment` + `state_skip` | 让 ≥80 万单据只经一人审批并付款 | 40 |
| L5 | `exposure` | 暴露面 | `path_traversal` + `ssrf_supplier` | 读出网关密钥 / 打通内网元数据 | 50 |

规则：

1. **解锁**：L(n) 通过才解锁 L(n+1)；也可以"自由模式"全开（给熟练者）。
2. **提示扣分**：每用一次 L2/L3 提示，扣该关卡 30% 分数（L1 提示免费）。
3. **每层独立开演**：点某层 → 只开这层需要的缺陷 → 跑一场 → 判定 → 记录进度。
4. **失败无惩罚**：可以反复复原重打（`restore` 已支持）。

| 已有能力 | 用来做什么 |
|---|---|
| `DefectFlag` | 每层只开对应缺陷 |

| 三级提示（brief / hint / command） | 提示扣分的基础 |
| `/lab` 管理台 | 展示关卡清单与进度 |

## 4. 分阶段实现

| 阶段 | 内容 | 状态 |
|---|---|---|
| A | 关卡清单 + 进度判定 + `/lab` 展示 | 本次做 |
| B | 按层开演（`POST /api/arena/start?level=`）+ 解锁门禁 | 下一步 |

| D | 外部靶标（Vulhub 容器）作为新关卡 | 更后 |

## 5. 设计原则（避免做成"flag 收集器"）

- **每层只教一件事**：题目描述先讲清"这一层在考什么"，再让人动手。
- **判据必须是攻击的副作用**：canary 泄露、状态被改、审批记录变少——而不是提交一个字符串。
- **允许失败**：失败一次不改分，鼓励反复试；提示才扣分。
- **蓝队也在场**：每层打完，蓝队给出对应规则或代码修复，学习者看到"攻破 → 修补"的闭环。

| 神秘关卡：不告诉目标，自己侦察（借鉴 PortSwigger Mystery Lab） | ✅ 已定义，判据待接 |

## 7. 两条硬约束（别违背）

1. **判据必须可验证**：canary 泄露、状态变更、mission 达成——不接受"提交一个字符串"。
2. **提示必须有成本**：否则所有人直接看答案，学习效果归零。
