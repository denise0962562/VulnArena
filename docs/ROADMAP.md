# VulnArena 路线图（2026-10 定稿）

> 这份文档记录"下一步做什么、为什么这么定"，以及被明确否决的方向。
> 目标：**一个人、两周、能讲清楚的项目**，用于投 Python 开发岗（安全是加分项）。

## 1. 定位

> 一个 **AI 生成安全规则的评测与上线系统**：模型提出 WAF 规则、做错误归因、生成绕过样本；
> 确定性闸门验收（召回 100% / 误杀 0% / 无 ReDoS）；通过的规则灌进真实靶场做端到端验证；
> 整套跑在 CI 里，指标退化就红。

三层结构，占比即投入：

| 层 | 内容 | 占比 |
|---|---|---|
| **核心** | `vulnarena/bench/`：语料、评测、AI 三处接入、报告、CI 门禁 | 70% |
| **验证** | `procure` + `arena`：真实系统 + 端到端演练 | 25% |
| **演示** | `/lab`、`/arena` 前端 | 5%（不再扩功能） |

## 2. AI 的三处接口（这是"AI 开发"的实质）

```
① 生成：模型写候选规则（结构化 JSON，多次采样）
        ↓
   闸门（确定性五项检查）── 否决 ──▶ ② 归因：模型看失败样本，说"漏在哪、误杀在哪、怎么改"
        ↓ 通过
   上线规则
        ↑
③ 扩充：模型生成绕过变体，把语料库变强（把靶场的红队压成离线步骤）
```

每一处都可量化：生成成功率、归因准确率（人工抽检 20 条）、新语料带来的召回提升。

## 3. 阶段与验收

| 阶段 | 内容 | 验收标准 | 状态 |
|---|---|---|---|
| **P1** | 底模加两个高危操作：支付、改密码（含前端页面） | 3 个新缺陷正反两面都有测试 | ✅ 本次完成 |
| **P2** | `bench` 评测台：语料 + 指标表 + JSON | `python -m vulnarena.bench run` 出召回/误杀/延迟 | ✅ |
| **P3** | 接 DeepSeek：`bench generate` 生成规则并自动过闸门 | 手写 vs 模型生成 的对比表 | ✅ |
| **P4** | 离线回合制自博弈：红造变体 → 蓝队规则被重新打分 | 79% → 70% → 66% 的召回曲线 | ✅ |
| **P5** | 前端总控台：一键跑一轮 + SVG 召回曲线 | `/lab` 的「自博弈曲线」卡片 | ✅ |
| **P6**（可选） | data factory：轨迹 → SFT 数据集，LoRA 微调小模型 | 留出场景上的提升数字 | 待做 |

## 4. 指标定义（写进 README，别改口径）

| 阵营 | 指标 | 定义 |
|---|---|---|
| 红 | 突破率 | 成功击穿的步数 / 总步数 |
| 红 | 被检出率 | 蓝队告警命中的攻击 / 总攻击 |
| 蓝 | TPR | 拦住的攻击 / 全部攻击 |
| 蓝 | FPR | 误拦的正常请求 / 全部正常请求 |
| 蓝 | 检测延迟 | 攻击发生到产生告警的轮数 |
| 系统 | 平衡线 | 在 FPR ≤ 0.1% 的前提下，能达到的最高 TPR |
| 系统 | 收敛轮次 | 达到平衡线所需轮数 |

**关键结论（写进 README）**：封闭漏洞集合里蓝队可以收敛到全拦；一旦允许红队生成新变体，
蓝队只能逼近"误杀可接受"的平衡线——**攻防不对称是结构性的，防守方不必也不可能"赢"**。

## 5. 信息不对称（保留，这是本项目最值钱的设计）

- **红队**：能看到全部指标、能复盘自己的每一步
- **蓝队**：只看得到日志；事件之后能拿到"事后报告"（哪个接口被打过），但拿不到攻击细节

沙盒里没有真实 IP 链，所以**溯源用合成指纹**：每个红队会话分发一个假指纹
（UA 片段 + 时间抖动 + 请求头顺序），蓝队练习"从日志把这些线索串起来"。
明确标注为**教学用合成信号**，不是真实溯源。

## 6. 明确不做（避免摊大饼）

- ❌ 真实溯源（沙盒里没有真实链路）
- ❌ 从零训练大模型（成本、数据量不在一个量级）
- ❌ 多租户平台、第二个业务域（一个域 + 五个高危操作足够）
- ❌ 继续扩靶场游戏化功能（关卡、段位、神秘关）

## 7. 现有缺陷清单（P1 之后共 10 个）

| 缺陷 | 类别 | 网关能拦？ |
|---|---|---|
| `sqli_search` | 注入 | ✅ |
| `sqli_login_bypass` | 注入 | ✅ |
| `idor_po_detail` | 越权 | ❌ 只能改代码 |
| `mass_assignment` | 业务逻辑 | ❌ |
| `state_skip` | 业务逻辑 | ❌ |
| `path_traversal` | 路径穿越 | ❌（正常文件名也含 `../`） |
| `ssrf_supplier` | SSRF | ✅ |
| **`payment_amount_tamper`** | 金额篡改 | ❌（网关不懂业务） |
| **`payment_replay`** | 重复付款 / 缺幂等 | ❌ |
| **`password_reset_idor`** | 账号接管 | ❌ |

**10 个里只有 3 个能靠网关解决**——这个比例本身就是最好的教学点，也是"WAF 不是银弹"的论据。
